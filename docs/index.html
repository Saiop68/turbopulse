turbopulse

A native rate limiter and distributed background job queue engine for Node.js, built with compiled Rust (via napi-rs) and Redis.

Native Memory Model

Queue items and token reservoirs reside directly in Rust heap memory. Job data is transferred via zero-copy Node.js Buffers to prevent V8 Garbage Collection pauses.

Non-Blocking Execution

All native Rust computations and Redis network I/O run on background Tokio worker threads, returning standard Promises that immediately yield to the libuv event loop.

Resilience & Recovery

Built-in distributed lock expiration heartbeats, exponential retries with jitter, and a single master timer wheel to avoid libuv timer min-heap overhead.

Core Concepts

1. What is Rate Limiting?

Rate limiting restricts how frequently an action or function can be executed over time (e.g. max 100 requests per minute, or max 5 concurrent operations). It protects APIs from exhaustion, prevents brute-force login attempts, and keeps third-party API bills under control.

2. What is a Background Job Queue?

In web servers, long-running operations (such as processing images, delivering emails, or compiling reports) should not block the HTTP request-response cycle. A queue stores the task payload, allows the API to respond immediately to the client with a 200/202 status, and delegates execution to asynchronous background workers.

3. Why Native Rust instead of Pure JavaScript?

Pure JavaScript implementations store jobs and rate-limit counters as JavaScript objects on the V8 heap. Under high throughput (thousands of tasks per second), V8's Garbage Collector must periodically pause the entire application to clean up temporary objects. TurboPulse stores queue records and tokens in native Rust memory, completely bypassing V8 GC pressure.

Installation

Install via npm:

bash 
npm install turbopulse

Pre-compiled native binaries are bundled for:

  • Linux: x86_64, aarch64 (ARM64 / AWS Graviton), musl (Alpine Docker)
  • macOS: Apple Silicon (M1/M2/M3/M4), Intel x86_64
  • Windows: x86_64

No local C++ compiler, Python, or Rust toolchain is required on client or production machines.

Quickstart

1. Rate Limiting Example

rate_limiter_quickstart.ts 
import { RateLimiter } from 'turbopulse';

// Limit execution to 2 concurrent tasks with at least 50ms spacing
const limiter = new RateLimiter({
  maxConcurrent: 2,
  minTime: 50,
});

async function run() {
  const task = (id: number) => limiter.schedule(async () => {
    await new Promise(r => setTimeout(r, 100));
    return `Task ${id} completed`;
  });

  const results = await Promise.all([
    task(1), task(2), task(3), task(4)
  ]);
  console.log(results);
}

run();

2. Background Queue & Worker Example

queue_quickstart.ts 
import { Queue, Worker } from 'turbopulse';

// 1. Create a queue
const emailQueue = new Queue('emails');

// 2. Register worker to process tasks
const emailWorker = new Worker('emails', async (job) => {
  await job.updateProgress(50);
  // Perform background work
  await job.updateProgress(100);
  return { delivered: true, recipient: job.data.to };
}, { concurrency: 4 });

emailWorker.on('completed', (job, result) => {
  console.log(`Job #${job.id} finished:`, result);
});

// 3. Enqueue jobs
await emailQueue.add('welcomeEmail', { to: 'user@example.com' });

RateLimiter API

The RateLimiter class controls concurrency limits, spacing, token reservoirs, and load shedding strategies.

limiter_config.ts 
import { RateLimiter } from 'turbopulse';

const limiter = new RateLimiter({
  maxConcurrent: 5,                   // Maximum parallel tasks
  minTime: 20,                        // Minimum delay (ms) between consecutive starts
  reservoir: 100,                     // Initial quota
  reservoirRefreshAmount: 100,        // Tokens replenished...
  reservoirRefreshInterval: 60 * 1000,// ...per interval (60 seconds)
  highWater: 50,                      // Queue threshold before strategy activates
  strategy: RateLimiter.strategy.OVERFLOW, // Drop incoming tasks when queue is full
  rejectOnDrop: true,                 // Reject promise with Error on dropped tasks
});

// Wrapping existing functions:
const safeFetch = limiter.wrap(fetch);
const response = await safeFetch('https://api.example.com/data');

Non-Blocking Tickets & Middleware

In web servers (Express, Fastify), you often need to permit or reject incoming requests immediately without queueing them up:

express_middleware.ts 
import express from 'express';
import { RateLimiter } from 'turbopulse';

const app = express();
const limiter = new RateLimiter({
  reservoir: 50,
  reservoirRefreshInterval: 1000,
  maxConcurrent: 10,
});

app.use('/api', async (req, res, next) => {
  const ticket = await limiter.tryTicket(1);
  
  if (!ticket.allowed) {
    res.setHeader('Retry-After', Math.ceil(ticket.retryAfterMs / 1000));
    return res.status(429).json({
      error: 'Too Many Requests',
      retryAfterMs: ticket.retryAfterMs,
    });
  }

  res.on('finish', async () => {
    await ticket.release();
  });

  next();
});

Multi-Tenant Groups

Isolate rate limits per user, route, or API key with shared base configuration:

groups.ts 
import { RateLimiter } from 'turbopulse';

const group = new RateLimiter.Group({
  maxConcurrent: 2,
  minTime: 25,
  reservoir: 60,
  reservoirRefreshInterval: 60000,
});

// Calling .schedule(id, fn) automatically creates an isolated limiter on first access
async function handleUserApiCall(userId: string) {
  return await group.schedule(userId, async () => {
    return await executeQuery(userId);
  });
}

// User A's traffic spike has zero impact on User B
handleUserApiCall('user_A');
handleUserApiCall('user_B');

Two-Tier Leased Limiter (L1 / L2)

Standard rate limiters issue a network roundtrip to Redis for every token, bounding single-thread throughput to ~20,000 ops/sec due to TCP network latency.

TurboPulse provides a Two-Tier L1/L2 Leased Architecture to achieve 2,000,000+ ops/sec against Redis:

leased_limiter.ts 
import { createTurboPulse, EngineMode } from 'turbopulse';

const engine = await createTurboPulse({
  mode: EngineMode.Redis,
  redisUrl: 'redis://127.0.0.1:6379',
});

const leasedLimiter = engine.createLeasedRateLimiter(
  {
    capacity: 100_000,
    refillRate: 100_000,
    refillIntervalMs: 1000,
  },
  'gateway_route',
  {
    leaseBatchSize: 500, // Leases 500 tokens per atomic Redis Lua roundtrip
    lowWatermark: 100,    // Pre-fetches in background when under 100 tokens
  }
);

// Served from local CPU registers in 250 nanoseconds
const permit = await leasedLimiter.acquire(1);

Queue Operations

queue_methods.ts 
import { Queue } from 'turbopulse';

const queue = new Queue('transcode', {
  connection: { host: '127.0.0.1', port: 6379 },
});

// Enqueue with options
const job = await queue.add(
  'encodeJob', 
  { file: 'video.mp4' }, 
  {
    priority: 10,                                              // Higher number = higher priority
    delay: 5000,                                               // Delay execution by 5000ms
    attempts: 4,                                               // Max retry attempts on failure
    backoff: { type: 'exponential', delay: 1000, jitter: true },// Exponential retry backoff
    deduplication: { id: 'file_video_mp4' },                   // Deduplication key
  }
);

// Atomic bulk enqueue
await queue.addBulk([
  { name: 'taskA', data: { id: 1 }, opts: { priority: 5 } },
  { name: 'taskB', data: { id: 2 }, opts: { priority: 1 } },
]);

// Maintenance
await queue.pause();
await queue.resume();
await queue.clean(60000, 1000, 'completed');
await queue.drain();
await queue.obliterate();

Workers & Processors

worker_setup.ts 
import { Worker } from 'turbopulse';

const worker = new Worker(
  'transcode',
  async (job) => {
    await job.log('Starting execution');
    await job.updateProgress(25);
    
    // Process task data
    const result = await processFile(job.data);
    
    await job.updateProgress(100);
    return result;
  },
  {
    connection: { host: '127.0.0.1', port: 6379 },
    concurrency: 8,                         // 8 parallel execution slots
    limiter: { max: 100, duration: 1000 },  // Rate limit worker execution
    lockDuration: 30000,                    // 30s lock before treated as stalled
    stalledInterval: 30000,                 // Stalled job recovery heartbeat
  }
);

worker.on('active', (job) => console.log(`Job ${job.id} active`));
worker.on('completed', (job, result) => console.log(`Job ${job.id} done:`, result));
worker.on('failed', (job, err) => console.error(`Job ${job.id} failed:`, err.message));
worker.on('stalled', (count) => console.warn(`Recovered ${count} stalled jobs`));

Job Lifecycle & State

job_state.ts 
const job = await queue.getJob('job_123');

if (job) {
  const state = await job.getState(); // 'waiting' | 'active' | 'completed' | 'failed' | 'delayed'
  console.log(`Progress: ${job.progress}%`);
  console.log(`Attempts: ${job.attemptsMade}`);
  console.log(`Return value:`, job.returnValue);

  await job.promote(); // Promotes delayed job to waiting queue immediately
  await job.discard(); // Fails the job permanently without further retries
}

Workflows & DAGs (FlowProducer)

Coordinate multi-stage dependencies where parent jobs wait for child tasks across different queues before executing:

flow_producer.ts 
import { FlowProducer } from 'turbopulse';

const flow = new FlowProducer({
  connection: { host: '127.0.0.1', port: 6379 }
});

// Parent job waits until all child jobs complete
await flow.add({
  name: 'generateMonthlyInvoice',
  queueName: 'billing',
  data: { customerId: 'cust_404' },
  children: [
    {
      name: 'fetchUsageMetrics',
      queueName: 'analytics',
      data: { customerId: 'cust_404' }
    },
    {
      name: 'fetchStripeCharges',
      queueName: 'payments',
      data: { customerId: 'cust_404' }
    }
  ]
});

Automated Systems

TurboPulse handles resilience, connection lifecycles, and scheduling automatically:

Stalled Job Recovery

If a worker node crashes mid-execution (OOM kill or SIGKILL), TurboPulse detects the expired lock lease and re-enqueues the job to a healthy worker.

Exponential Backoff & Jitter

Calculates delay * 2^attempts with ±20% randomized jitter, preventing thundering-herd synchronization spikes on downstream services.

Connection Multiplexing

All queues and limiters targeting the same Redis instance share a single native connection pool, eliminating client socket exhaustion.

Hierarchical Timer Wheel

Collapses thousands of tenant rate limit schedules into 1 master timer in Node.js, eliminating libuv timer min-heap thrashing.

Asynchronous Token Pre-fetching

Leases token batches from Redis in the background, serving hot-path permits from local memory in 250 nanoseconds.

Multi-Tenant Auto-Provisioning

Calling group.schedule(id, fn) provisions isolated limiters on demand and cascades configuration updates across active instances.

Stale Key Sweeping

Tracks last-accessed timestamps on rate limiter buckets, freeing idle memory in high-cardinality visitor environments.

DAG Dependency Resolution

Tracks multi-level child dependency trees in atomic Redis keys, automatically promoting parent jobs with child output attached.

Event Loop Guarantees

Non-Blocking Event Loop Verification

Under continuous load, TurboPulse's mean event loop delay is 14.4 ms (matching the operating system baseline timer quantum). Node.js never stalls.

  1. Tokio Worker Pool: All native Rust computations and Redis network I/O run on background Tokio worker threads.
  2. Zero Spin-Locks: Wait periods use asynchronous timers and libuv check-phase ticks. CPU usage during waits is 0.0%.
  3. Guaranteed Concurrency Release: Permits are released inside finally blocks, guaranteeing zero slot leakage even on unhandled exceptions.
  4. Runtime Input Validation Guards: Validates numeric bounds, non-empty strings, and executable functions at runtime, throwing clean TypeError exceptions at call sites.

Configuration Reference

LimiterOptions

Property Type Default Description
maxConcurrent number undefined Maximum parallel operations allowed.
minTime number 0 Minimum delay (in ms) between consecutive operations.
reservoir number undefined Initial token budget available.
reservoirRefreshAmount number undefined Tokens added per refresh window.
reservoirRefreshInterval number undefined Duration of the refresh window in milliseconds.
highWater number undefined Maximum queue depth before drop strategy applies.
strategy Strategy LEAK Drop strategy: LEAK, OVERFLOW, BLOCK.
